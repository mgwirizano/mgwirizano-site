# Inspect before accepting future-credit instructions — v4.4

Inspect now checks all fund obligations for every identified member, not only funds named in the memo. The table distinguishes paid, partial, exempt, current unpaid, overdue and unverified balances, with paid cash, applied credit and current remaining amount. A deadline passing does not label an already-paid fund overdue.

For the Wezzie-style $100 payment naming two members and Mtileni, two verified $15 named-fund shares may still be prepared. If either member has another unpaid fund or any unverified fund balance, the assistant does not propose $35 future credit each. It leaves $70 unallocated and recommends reviewing the other balances and confirming the intended allocation with the member. It does not move the payment to an unnamed fund or split that remainder automatically.

If all other funds are verified paid, covered or exempt, the normal editable future-credit suggestion remains available. Choosing Use suggestions rechecks current records, so newly found debt prevents the earlier automatic credit proposal. Inspect also returns the all-fund context for posted/protected rows.

This is a payment-instruction/account-balance check. It is not proof that a bank transfer occurred and does not approve a funeral benefit claim. Explicit manual allocations still use the existing reviewed preview and confirmation workflow. No financial write or email occurs during Inspect.

Replace the supplied addon files and website scripts together and deploy a new version of the same Apps Script web app. No extra trigger or configuration is needed for this Inspect change. All previous v4.3 processing and follow-up features are included.
